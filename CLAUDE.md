## What this repo owns

The Next.js 16 App Router site on Vercel. It renders what the API decides and holds
no business logic — no scoring, no ranking, no lineup maths. If you find yourself
computing a recommendation here, it belongs in `waiver_priority`.

## Verify before you claim anything works

```bash
npm run lint && npm run typecheck && npm run build && npm run check:client-boundary && npm run test:e2e
```

`npm run test:e2e` runs Playwright against `npm run start`, which serves the
**built** output. A source change you have not rebuilt will be tested as the old
build and pass for the wrong reason — always `npm run build` first.

`npm run dev:stack` brings up web plus API together for local work.

## Things that will bite you

- **Vercel preview builds fail by design.** `prebuild` runs
  `scripts/check-hosted-config.mjs`, which refuses any hosted build lacking the
  seven required variables. The Preview environment does not have them, so every
  preview deploy fails at the 4-second mark. Production has them. This is
  configuration, not a code error — do not "fix" it by weakening the check.
- **Server secrets must never reach the bundle.** `check-client-boundary.mjs` greps
  the built output for them and includes a canary so the check itself is falsifiable.
- **The API contract is mirrored in three places** — `src/lib/api/contracts.ts` (Zod,
  the runtime gate), `tests/fixtures/mock-api.mjs` (what Playwright serves), and the
  API's own `tests/test_api_contract.py`. A response-shape change needs all three.
- **New response fields should be nullable with a default**, so the page renders
  correctly against an API that has not deployed yet. `scoring_audit` is the pattern
  to copy.
- The league board sets `export const maxDuration = 60`; the API client budgets 45 s
  for a recommendation with one retry on 502/503/504.
